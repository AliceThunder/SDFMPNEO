\section{实施路线与软件边界}

\subsection{阶段划分}
实现必须按依赖顺序推进，避免再次出现理论、优化器和性能补丁同时演化的情况。

\paragraph{Phase A：物理数据接口。}
只新增产生 $G(a,g)$ 的确定性 API 和测试，不引入神经网络。目标接口应接近：
\begin{equation}
\texttt{quadratic\_joule\_tensor(state, geometry)}\rightarrow G.
\end{equation}
该层负责 multi-RHS EM solve、对称张量构造、数值等价测试和缓存。

\paragraph{Phase B：数据集与 POD。}
实现可重启的数据生成器、数据 manifest、train/validation/test split、POD 构建和版本签名。数据格式至少保存：状态、几何、$G/y$、solver/ROM 版本、误差证书摘要。

\paragraph{Phase C：独立神经模块。}
引入 PyTorch residual MLP、归一化器、POD decoder 和 quadratic-current layer。该模块仅依赖离线数据，不依赖时间积分和生产模型入口。

\paragraph{Phase D：神经电热向量场。}
实现
\begin{equation}
F_\theta(a,g,u)=M_r(g)^{-1}[-K_r(g)a+q_\theta(a,g,u)]
\end{equation}
以及与真实 reduced vector field 的逐点对照测试。

\paragraph{Phase E：时间积分。}
先实现参考可靠版（例如高精度 solve\_ivp 调神经向量场）作为测试 oracle，再实现 ETD2/IMEX production integrator。两者在步长收敛区内必须一致。

\paragraph{Phase F：模型封装。}
接入 train/save/load/predict/steady-state API；保留旧模型读取兼容层，但新格式必须显式记录 architecture version、POD basis、normalization、network state 和训练域。

\paragraph{Phase G：性能与生产切换。}
完成 Gate 1--7 后才切换默认训练入口；在此之前不删除旧实现。

\subsection{建议模块边界}
最终软件结构建议按职责划分，而非按训练技巧划分：
\begin{verbatim}
sdfmpneo/
  electrothermal_tensor/
    quadratic_joule.py       # G(a,g) exact/reduced physics construction
    dataset.py               # snapshot generation and manifests
    pod.py                   # output compression
    network.py               # residual MLP only
    physical_layer.py        # beta -> G -> q
    vector_field.py          # M,K,q composition
    integrators.py           # ETD2 / IMEX
    model.py                 # save/load/predict facade
    validation.py            # G/q/F/trajectory audits
\end{verbatim}
具体目录名可在编码时调整，但职责边界应保持。

\subsection{禁止的耦合}
实现中禁止以下设计回归：
\begin{itemize}
  \item 网络 forward 内部调用 EM solver；
  \item 优化器 candidate acceptance 调用 full physics；
  \item 把 $M_r,K_r$ 当作网络输出；
  \item 网络直接输入时间并绕过 ODE；
  \item 在数据生成时把大量 $u$ 当成独立昂贵样本，而不利用 quadratic-current 消元；
  \item 将 validation set hard points 自动回流后仍继续称其为 validation；应创建新的冻结 test set。
\end{itemize}

\subsection{模型持久化}
新模型文件必须保存：
\begin{itemize}
  \item 模型格式版本与 Git revision；
  \item thermal basis / geometry chart 的兼容签名；
  \item $\bar y,U_K$；
  \item input/output normalization；
  \item 网络结构配置和参数；
  \item training domain；
  \item 数据集 manifest/hash；
  \item 训练指标和 frozen test 摘要；
  \item 可选 stability analysis 摘要。
\end{itemize}
加载时任何关键维度/签名不一致必须 fail closed，不能静默重解释。

\subsection{训练可复现性}
每次正式训练记录：随机种子、数据版本、POD rank、batch size、optimizer、learning-rate schedule、precision、hardware summary 和 early-stopping checkpoint。标签数据版本与网络训练版本分离，使网络超参数实验不重复生成昂贵物理数据。

\subsection{并行化策略}
并行化优先级固定为：
\begin{enumerate}
  \item 物理 snapshot 之间的 embarrassingly-parallel 并行；
  \item 单 snapshot 内 multi-RHS EM solve；
  \item GPU mini-batch NN training；
  \item inference batch 并行。
\end{enumerate}
不在首版为单条 trajectory 设计复杂跨步并行，因为时间积分存在自然数据依赖。
